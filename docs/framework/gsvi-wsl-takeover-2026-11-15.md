# GSVI：WSL 直接接手记录

本轮接手前已保留原始源码与静态参考，两个源码仓库保持相邻布局。实际操作回执及工作路径保留在本机归档。

接来的第三稿是未完成的工作树，不能把第二稿交接报告当作第三稿验收。WSL 首次 Core 类型检查确实失败：Core 的解析测试跨仓库导入插件源码，导致公共 SDK 别名解析失败。已将插件语法测试归回插件仓库，Core 只验证自身 Unicode 辅助函数。也修复了 Python 整数语义中的负零、取消后目录操作继续处理、长等待轮询定时器上限及重复查找 Job 操作的问题。自动呈现的文本规范化统一走 Python strip 语义，避免概率/长度选择与真正发送的文本不一致。

继承的新能力包括受管目录引用和分块读取、按同一服务版本验证选择、超过 300000ms 的服务总期限以及原 chat_send/delivery.send 的有序逻辑消息组。它们已经接到真实消费者；仍需按原源完整矩阵审核，不能因类型检查或打包成功就称动态验证完成。配置响应新增 gsvi-plugin@1 标记，升级脚本必须核对，防止把依赖这些能力的包安装到旧 Core。

静态 schema 对照逐项比较原部署 schema 的全部属性，13 个叶字段、preset 嵌套结构、默认值、说明、hint、secret、options 和 slider 均保留。凭据通过插件同页入口编辑，由 Core 托管；Worker 不取得连接参数。

分层判断：Bot 应提供配置密钥投影、受管服务、内容引用/分块传输、可信发送来源、取消/期限及真实 ACK；插件负责语音策略、命令语法、角色选择和是否转换的业务决定。当前 GSVI 配置投影仍是固定协议适配，不能宣称已提供通用插件配置生命周期或任意 HTTP 能力。Pi 继续负责会话和工具循环。后续审核应检查这些支持是否真正减少业务耦合，而非把更多语音业务搬进 Coordinator。

本轮只运行类型检查、纯解析/配置和无语音操作的收据/取消检查，再构建 Core UI 与 GSVI 单包。没有执行音色查询、刷新、试听、合成、下载或工具内呈现；没有修改 NAS 正式服务、启用状态或 ComfyUI。未运行禁止的旧全量音色测试。正式 19335 的 GSVI 仍是接手时的停用版本，不能把本地包称为已经安装。
