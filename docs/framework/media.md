# 会话媒体、引用与本轮视觉

第三阶段 B1 将媒体输入拆成平台引用、范围内缓存和模型请求投影。一个群仍共享同一主对话；图片的发言者只用于来源标注，不增加权限。

## 处理链

1. OneBot 数组或 CQ 字符串解析为文字、媒体引用与回复 ID。消息立即入库；普通未触发消息不因为被收到就下载图片。
2. 私有 `media` 记录保存平台文件标识和签名 URL。公开消息、运行快照及模型只收到媒体 ID、本地访问路径和来源。浏览器查看或 Agent 使用时按需下载，缓存在当前范围的 Artifact Store。
3. 根输入固定附件和引用来源。通过 Pi durable 公共 `GenerationTask.beforeRequest` 钩子为本次请求临时装配像素；原始 transcript 只写入媒体引用。引用正文同样按本次预算投影。
4. 主模型直接读取图片，不额外运行一个图片描述模型。后续纯文字输入不重发旧图片；需要复看时使用显式引用或 `media_read`。

默认每次请求最多 4 张图、最长边 1536 像素、4 MiB Base64 总量，使用 Pi 公共 `resizeImage` 处理。近期显式工具读取优先于自动附带图片。所有设置支持既有的默认、账号、范围、对话继承和版本检查。轨迹显示实际投影张数与编码大小；真实 token 用量继续使用 Provider 返回值，字节预算不冒充 token 测量。

模型组内图片请求跳过配置为不支持图片的候选。整个组没有图片模型时提供明确的未载入说明，文字请求仍可执行，不把空占位伪装为看过图片。

## 读取与容器传递

`media_read` 接受当前范围的 `media` 或 `artifact` ID，不能传入任意 URL 或宿主路径。`stage=true` 额外需要 `write` 能力，把文件传到当前运行的远程容器 `/workspace/.bot-media/`；后台 Agent 使用自己的沙盒。没有执行后端时仍可读取图片，不能落到宿主文件工具。

Web 支持上传、移除待发附件、引用已有消息以及切换页面后保留草稿。单个上传/下载上限为 8 MiB，每条消息最多 12 个附件。自动下载和图片解码分别有并发上限；文件大小与原始尺寸在解码前检查。

QQ 官方图片域名内置在适配器中；非标准媒体服务可在「QQ 接入 → 配置连接 → 额外媒体来源」填写完整 HTTP(S) origin。每次重定向重新核对来源，下载不会转发 LLM/NapCat 凭据。平台返回的文件路径不会当作宿主文件读取。失败媒体保留引用，可在网页重试。

## 引用与撤回

优先使用当前范围已记录的引用。未观察到的 QQ 消息通过 `get_msg` 读取，只有响应可证明属于当前群/私聊才使用；缺少范围证据或查询失败保留“未观察到”，不拼接其他范围内容。引用发言者不会成为本轮调用身份。

QQ 撤回通知写入持久记录，包括先于原消息到达的通知。已撤回来源不再自动载入，聊天历史投影返回撤回标记。一个逻辑回复有多条平台消息时分别记录撤回 ID，部分撤回与全部撤回保持区别。撤回聊天消息不删除此前已经完成的任务产物。

音频、视频和文件作为附件保留，可下载或转入沙盒。此阶段不宣称内置语音识别或视频理解已经完成。

## 验证依据

- 假 Responses 请求载荷确认缩放尺寸、本轮图片、下一轮无重复像素、显式引用重载和工具图片优先级；native conversation entries 中没有自动注入的图片正文。
- 假 NapCat 验证 CQ/数组解析、@Bot 触发、签名 URL 不进入模型、跨群引用拒绝、撤回与迟到回执。
- 共享浏览器验证桌面/手机上传、引用、设置修改、模拟 QQ WebSocket、进程重启后缓存复用；没有真实 QQ 测试发送、付费模型调用或生产容器操作。
- 测试目录通过 `bunfig.toml` 限定，避免 Bun 将数据备份中的旧测试重复发现。

Responses 的图片工具结果格式复用 Pi 原生转换。OpenAI 官方 [Function calling](https://developers.openai.com/api/docs/guides/function-calling/) 文档确认 `function_call_output.output` 可传图片/文件对象数组；已实际获取页面核对，未根据旧字符串输出假设自行改写协议。
