# 持久外部任务与 Cron

第三阶段 B2 把协议支持的远端任务和计划入口接入同一套 Job、权限、取消与交付机制。Pi durable 仍负责持久任务阶段、睡眠和恢复，Bot 负责平台、能力绑定及生命周期。

## MCP Tasks

目录刷新保存 MCP Tasks 能力声明。只有服务声明 `tasks.requests.tools.call` 且工具声明 `execution.taskSupport` 时，才使用标准任务协议。`required` 工具自动返回框架 Job 回执；`optional` 工具默认保留普通短调用，显式 `start_job` 时使用远端任务协议，也可在 MCP 配置中选择全部自动转后台。后台调用不会额外启动一个 LLM。

执行分为提交、持久等待、取结果、交付：

- 在提交前写入 `dispatching` 检查点，收到回执后原子保存远端任务 ID、HTTP 会话和下一阶段。
- 等待使用 durable `sleepUntil`，按远端建议间隔或配置默认值查询。只重试只读查询；未知提交不重新提交。
- Bot 重启恢复原会话，JSON-RPC 请求 ID 在每次连接间保持唯一。远端 HTTP 会话失效时，可重新初始化并查询原任务 ID，仍不重新提交。
- `tasks/result` 的正常结果、工具错误和 JSON-RPC 失败分别处理；TTL 是接收方可删除记录的保留期提示，不把本地时间越过 TTL 当作任务已消失。
- 使用固定的连接配置与能力快照收尾；显式环境变量引用仍由部署环境提供。权限撤销、资源停用和会话切换会停止普通查询，并尝试取消这项已持有的任务。
- 关闭本地轮询连接不发送 DELETE；只有结果或取消事实已保存后，才结束它专用的远端会话。会话标识保存在私有 durable 文档中，API、模型和事件不返回它。
- `input_required` 会显示远端等待输入并尝试结果流；当前不声明 sampling/elicitation，不擅自执行远端请求的模型调用或确认。完整的交互能力仍属后续扩展。

每个 MCP 服务可设置等待任务上限、默认轮询间隔和连续查询失败上限。名额按服务持久记录，排队不占主对话或模型请求额度。这个上限控制 Bot 等待的任务数，不能替代远端 GPU 的实际资源调度；结果不明时释放本地等待名额，也不声称远端计算已经停止。

JSON 响应在解析前限制为 8 MiB，SSE 继续使用 Pi 的事件预算。二进制结果沿用范围内 Artifact、媒体交付和发送账本。模型工具返回包含读取指引，用户收到的结果摘要不夹带这些内部指引。

## 取消与核对

本地停止等待、远端确认取消、提交/取消回执未知是不同状态。取消前保存发送标记；重启不会重复发出未经确认的取消请求。若任务刚好完成，则保留结果并按取消意图停止交付。

网页对持有远端回执的未知任务提供“核对远端状态”和“取消远端任务”。这些显式操作只使用已保存的远端 ID，不创建新任务，不再次发群消息。查到的结果可在任务页查看和下载。未收到任何远端任务 ID 的未知提交无法凭空恢复，只保留明确状态供核对。

## Cron 入口

每次受理的计划触发也是 Job，包含计划 ID、触发键、时区、原定时间、创建者身份和能力上限。相同触发键只受理一次。防重叠记录与 Job 在同一个 durable commit 中保存，重启后继续生效；尚未受理的停机期间触发默认跳过，不积累一串补发回复。

独立上下文是默认选项：每次创建新的子 conversation，工作区固定为该计划的 Cargo；子 Agent 和外部操作归属于本次工作，计划可以等待它们，再统一交付最终结果。共享主对话选项沿用群上下文和工作区；长任务可转交后台，主对话先返回，后台孩子继续运行并交付。防重叠覆盖尚未结束的孩子，不只检查主任务是否返回。

“暂停自动执行”只控制未来触发；“停止本次工作”取消这次工作及其孩子。删除先关闭受理再取消已有工作，执行代际阻止尚在受理中的请求在删除后复活。旧版尚在恢复的计划 run 会临时阻止该范围的新计划工作，避免升级时重复操作原工作区。

后续触发使用最新群设置；已受理工作保存配置快照。工具权限继续与创建者上限求交，新增资源不会自动授予旧计划。计划触发时间和时区作为任务参数提供给模型，恢复时保持原值。

## 现有边界与验证

这次实现标准 MCP Tasks。普通 MCP 长调用仍可放入 Job，但没有任务协议就不会猜测远端任务 ID 或宣称可恢复轮询。其他业务 API、插件操作和人工等待需要通过后续驱动接入同一生命周期。

测试覆盖正常和丢失回执、会话恢复与重新连接、唯一请求 ID、查询重试、取消竞争、权限撤销、显式核对、响应预算，以及 Cron 去重、防重叠、共享/独立上下文、持久文件、孩子收集和删除竞争。使用内存宿主状态、JSONL durable 存储及假服务，没有新增数据库单元测试。

协议依据：[MCP Tasks 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)。已通过共享浏览器读取原文，核对 capability、taskSupport、状态转换、取消、TTL 与结果返回规则。使用 Pi 1.5.0 的公开 client/transport API，没有修改 SDK 私有字段。
