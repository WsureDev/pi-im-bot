# Improve：吸收设计思想的实施方案

## 目标与边界

统一 Agent 执行机制、降低核心模块耦合、把平台协议和存储适配做成可验证的边界。保留当前 Vue 工作台、资源提供者与插件端口设计。先明确依赖方向，不进行全仓 workspace 搬迁或格式工具切换。

## 实施项与验收

1. **Durable 唯一执行路径**：Coordinator 通过领域内的执行接口连接 Durable；删除生产旧 runPi 路径和它独有的限流器。未装配执行器时显式失败，不能静默回退。旧引擎测试改用真实 Durable 测试入口，保留授权、故障转移、取消和副作用断言。
2. **缩小 SDK 依赖**：Provider 直接构造 pi-ai 模型，图片处理使用 Durable 的公开 API，工具基础契约改为 pi-agent-core。旧会话导入作为单独的按需加载桥接。文件／Shell 与 Skill 继续使用 coding-agent 的公开工具 API：Durable 工具接口并非现有 Shipyard operations 接口的直接替代，不能为删除依赖而重写远程隔离行为。因此暂保留该依赖，用途收窄为工具／技能适配与旧会话导入。统一 Pi 包版本，保留配置快照和旧运行记录的处理。
3. **清晰的服务边界**：把 HostToolServices 契约与工具实现分离，Coordinator 依赖执行接口而非 Durable 实现；把通用 Bun SQLite 适配器移至存储域，继续使用原来的串行事务、WAL、关闭和文件权限策略，不引入第二套实现。禁止增加数据库测试。
4. **OneBot 协议进入实际链路**：提取实际使用的动作及结果 schema，适配器在请求边界校验回复。以 Zod 作为当前运行时契约来源，保留 NapCat 扩展和未知消息段；不同时引入三套协议定义，也不引入未接入的 HTTP SDK。验证标准动作、扩展动作、错误响应和 ID 表示。
5. **保留 Bot 策略**：继续由宿主管理授权、消息交付、任务预算和工具闲置卸载；用 Durable 原生工具执行和搜索机制承载这些策略，不因代码减少而改变产品行为。
6. **利用现有 Web 分离**：沿用 dashboard 的 Vite 开发服务和 API/WebSocket 代理、生产静态构建。提供统一开发命令，子进程共同关闭，避免部署第二套工作台或新增本地访问口令。

## 验证与交付

- 先记录继承基线的 check/tests 结果，再运行受影响的业务测试。
- 必须完成 bun run check、bun test tests、bun run build；涉及开发启动脚本时使用隔离命令验证退出和清理，不能启动正式 Bot。
- 不使用生产 QQ、真实模型或生产插件容器进行验证。
- 将新增改动单独提交，保留继承快照与实现提交的区别；记录验证结果、限制和后续可选演进。

## 后续可选演进

领域接口稳定后再评估拆包。需要独立发布 OneBot 客户端时再增加从契约到文档／客户端的生成流程。工具卸载策略变更和双服务生产部署需分别通过收益评估，不作为本次实施前置条件。

## 实施结果

- Coordinator 只受理 Durable 任务，执行器未装配时拒绝受理和恢复，禁止重复装配；配置快照成为必备依赖。仍保留旧记录的 engine 字段与旧会话导入，避免破坏已有数据。
- `agent/runtime.ts` 定义宿主使用的执行／持久任务能力；任务、观察器和资源适配使用该接口。`agent/services.ts` 独立定义宿主工具服务。`plugins/execution.ts` 仅暴露 Agent 需要的可用性、操作执行和 Hook，避免依赖插件管理实现。
- `capabilities/tool.ts` 基于 pi-agent-core 定义 Bot 工具，不继承 CLI 扩展上下文与渲染器。Provider 直接构造模型描述，候选组／故障转移仍由原有请求网关负责。
- Pi 包统一固定为 1.5.2。图片处理使用 Durable 的 Photon 接口。上下文压缩直接配置在 Durable 会话，不再维护模型 ID 到压缩开关的额外映射。
- 删除旧 runPi 和旧曝光扩展；保留其业务断言，改由 Durable 执行。按需工具实际使用会刷新最近使用轮次，持续使用不提前卸载；闲置超限和权限撤销仍会移除工具。
- SQLite 适配器移至 `storage/durable-sqlite.ts`，只有一个实现，事务和宿主文件策略保持；没有新增数据库测试。
- OneBot 支持动作集中在 `channels/onebot/actions.ts`。请求参数、普通发送／NapCat 合并转发回执、查询结果在边界校验；拒绝失败状态伪装的成功回执、缺失消息 ID 和不安全的数字 ID，保留精确字符串 ID。校验失败不重发消息。
- `bun run dev` 启动 Bot 与现有 Vue/Vite 工作台；子进程独立进程组，任一退出或收到停止信号时共同关闭。单独后端使用 `dev:bot`。测试用短生命周期模拟进程验证清理，没有启动正式 Bot。
