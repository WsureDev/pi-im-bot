## 第一阶段：共享会话与配置基础（2026-11-09）

已经实现并接入 QQ、Mock、Pi 和 Cron：

- Room 是稳定聊天范围，地址由平台、机器人账号、群/私聊 ID 与可选话题构成；`currentConversationId` 是全群共同选择。Conversation 单独存储，Pi 仍保存模型历史与工具循环。
- 新建和切换对话停止此范围的在途与排队任务，增加 `conversationEpoch`；新成员不会创建另一份 Agent 用户状态。宿主消息记录和容器 Cargo 随聊天范围保留。
- `framework.json` 保存默认设置、账号覆盖和人格资源；范围与对话覆盖在 Bot SQLite 中。优先级为默认 → 账号 → 范围 → 当前对话。后台 Cron 对话继承关联主对话设置。
- 每次受理固定人格内容/版本、有效设置、来源说明、触发身份和授权上限。设置不产生额外 LLM 请求；权限规则在工具执行前重新检查。
- 数据设置控制发言者、时间和历史读取预算；回复偏好进入系统提示；Agent 开关、主动发送、超时、模型调用上限实际生效；输出裁剪不改写模型原文。
- 已注册工具可全选或明确选择。第一阶段提供全量策略，第二阶段加入 Pi 原生按需搜索与装载。
- 网页提供人格编辑、四层覆盖、恢复继承、当前生效值及来源、共享对话选择和任务配置记录。设置写入带版本冲突检查。

### 身份与权限

QQ 身份只从适配器收到的平台事件生成；Web/Mock 的昵称和 ID 是显示标签。网页直连属于本地操作入口，配置管理不额外添加登录门槛。这里的工具规则约束 Agent 调用，网页设置管理属于可信本地操作。

权限默认保持当前已开放能力。需要限制时设置 `permissions.default` 和规则；显式 deny 优先。规则可匹配 `everyone`、`local`、`mock`、具体平台用户或平台角色。相同规则下，多个触发人的权限取交集。`*` 仅用于权限规则，不用于工具选择集合。

例如仅允许指定 QQ 用户使用 Shell：

```json
{
  "default": "deny",
  "rules": [
    { "effect": "allow", "capabilities": ["chat_history"], "subjects": [{ "kind": "everyone" }] },
    { "effect": "allow", "capabilities": ["bash"], "subjects": [{ "kind": "platform-user", "channel": "onebot-v11", "accountId": "机器人QQ号", "actorId": "成员QQ号" }] }
  ]
}
```

一旦允许任意 Shell，用户原定的“容器内一切不限制”继续成立；这是工具调用授权，不是容器内系统调用或网络隔离。当前角色来自本次可信平台事件，不额外查询成员角色变化；规则调整在下一次调用即时检查，不中断已经发出的远程操作。

Cron 保存创建者身份和能力上限，执行时取该上限与当前规则的交集。旧计划若缺少来源，暂停自动执行并在网页标出，用户可以明确以本地操作员重新授权。普通重新运行计划不会提升权限。

### 数据迁移与接口

首次启动将 `bot.json` 中原人格、超时、请求上限和 Provider 默认组用于生成 `framework.json`，以后这些设置以新文件为准。原字段仅保留为首次生成的迁移输入；已有新文件不会被覆盖。

旧 Room 的模型组迁为范围覆盖，当前 Pi 目录映射保存在 Conversation 的 `sessionKey` 中，因此当前上下文继续恢复。旧消息缺少 conversation ID 时保持范围级历史，不伪造归属。旧 Pi 目录、Shipyard 绑定与 Cargo 不移动。新增 conversation 表和范围当前指针在事务中保存。

主要接口：

| 接口 | 用途 |
| --- | --- |
| GET /api/framework | 设置、人设和内置能力列表 |
| PUT /api/framework | 带版本保存默认、账号设置及人格 |
| GET /api/rooms/:id | 范围、对话列表、有效配置和来源、消息/任务 |
| PATCH /api/rooms/:id | 带 revision 更新范围配置 |
| POST /api/rooms/:id/conversations | 新建并选择共享对话 |
| POST /api/rooms/:id/conversations/:conversationId/select | 切换共享对话 |
| PATCH /api/rooms/:id/conversations/:conversationId | 带 revision 修改标题和对话覆盖 |

验证覆盖：共享历史与人格变更、恢复旧对话、权限不串用、调用时撤销、Mock 身份不可冒充平台、多人权限交集、Cron 权限继承、空覆盖继承、旧映射保留、输出/历史投影。使用内存状态与假 Responses 服务，无数据库测试、真实群发送或付费模型调用。共享浏览器完成桌面/手机页面验收。

## 第二阶段：能力目录、HTTP MCP 与 Skill（2026-11-09）

新增「能力资源」页面，资源配置存入 `config/resources.json`。MCP 服务和 Skill 包分别登记、启停、刷新，不加载第三方代码到 Bot / Pi 核心进程。资源登记、启用、目录/包可用、范围选中、触发授权、实际装载是独立条件。

工具收纳单选 `all` 或 `deferred`。后者使用 Pi 1.5.0 公共 `createToolSearchExtension`，搜索与加载直接复用 Pi 的实现；常驻集合和闲置保留轮数可配置，装载状态保存为 Pi 自定义会话条目，不进入模型上下文。Skill 说明在按需模式下也通过搜索装载。隐藏工具不代表撤销权限，搜索不能重新启用未授权工具。

HTTP MCP 使用官方 `@earendil-works/pi-mcp@1.5.0`：

- 支持 Streamable HTTP、固定 Headers 与显式 Header 环境变量映射。Header 的 `!command` 和 `${VARIABLE}` 都按字面传输；只解析配置的 `headerEnv`，不启动 stdio 子进程或宿主命令。
- 网页“连接并刷新目录”只执行协议初始化和工具发现。连接地址的查询参数和 Header 值不回显；留空 URL 与凭据占位保留已保存值。
- 工具按稳定能力 ID `mcp:<服务ID>/<原始工具名>` 授权；模型别名独立生成。权限规则可使用 `mcp:<服务ID>/*`，范围资源选择和工具选择继续收窄能力。
- 每次调用受硬期限和取消信号约束；调用失败不自动重试。实际调用前核对登记的 schema，变化时要求刷新，避免让旧任务按新定义执行。要求 MCP Tasks 的工具目前显示为未装载，留待异步任务阶段接入。
- 大段文本结果裁剪到 12000 字符，完整公开结果保存为当前聊天范围的 Artifact，模型可用 `artifact_read` 分页获取；MCP 私有 `_meta` 不提供给模型。只返回产物 ID，不返回宿主文件路径。

Skill 复用 Pi 的标准 `SKILL.md` 元数据解析及提示格式：

- 网页登记 Bot 机器上的技能目录，根部必须有 `SKILL.md`；导入保存内容固定的版本，保留相对目录和二进制资源，不执行脚本。
- 包拒绝符号链接，限制 200 个文件 / 32 MiB，单文件 5 MiB；跳过 `.git`、`node_modules`、`.venv` 和 `__pycache__`。读取固定版本时验证内容摘要。
- 能力 ID 为 `skill:<ID>`。Agent 调用对应 Skill 工具时把包上传到现有沙盒 `/workspace/.bot-skills/<ID>/<版本>/`，再通过现有容器文件/Shell 工具运行脚本。没有执行后端时仍可读取说明和文本资源，不能执行脚本。
- 来源目录修改不会改变已经受理任务使用的版本；导入新快照后供新任务使用。容器内仍遵循用户“不限制”的约定，包文件被加载到该会话容器后属于这个会话的可访问数据。
- `/skills` 列出当前触发人获准使用的包；`/skill ID 内容` 显式提供该包给本轮 Agent。`disable-model-invocation` 的包仅在显式指定时提供，仍需授权。QQ 可直接发送上述指令。

新计划保存完整能力上限，已有计划不会自动获得以后新增的 MCP/Skill。网页可显式“以本地操作员更新权限”。在途任务另保存能力版本摘要，凭据不会写入任务快照。

当前验证：42 项测试覆盖前述共享会话和边界，以及工具搜索/闲置回收、MCP 发现/调用/失败/超时/停用/schema 变化、凭据保留、长结果分页、Skill 导入/固定版本/沙盒文件映射。共享浏览器端到端完成 MCP 与 Skill 网页配置和聊天执行，桌面/手机布局通过。测试使用本地假模型、MCP 与 Bay，未执行真实群发送、付费模型请求或生产容器操作。
